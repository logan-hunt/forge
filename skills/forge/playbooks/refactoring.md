### Refactoring

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, report it separately and keep the structural change against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to the [figure-it-out](../../figure-it-out/SKILL.md) skill. This playbook is the focused-to-medium change.

1. Pin the behavior contract first. Run the [how](../../how/SKILL.md) skill over the affected subsystem to learn the contract, then identify a meaningful existing test, snapshot or equivalence check that captures the affected behavior before structure moves. Add a focused pin when the preservation risk warrants it; whitespace or a straightforward local rename does not need a new harness. Type check and lint alone do not prove behavioral equivalence for a substantive reshape.
2. Name the structure the code is missing per [principle-model-the-domain](../../principle-model-the-domain/SKILL.md). Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today ([principle-foundational-thinking](../../principle-foundational-thinking/SKILL.md), [principle-redesign-from-first-principles](../../principle-redesign-from-first-principles/SKILL.md)). In Max, or when ownership and contracts need a new shape, run [architect](../../architect/SKILL.md) for parallel design exploration before the move.
4. Subtract before you add. Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape ([principle-subtract-before-you-add](../../principle-subtract-before-you-add/SKILL.md)). The smallest change that reaches the target shape ships ([principle-laziness-protocol](../../principle-laziness-protocol/SKILL.md)). A speculative cleanup that "might help" gets reverted.
5. Move in small behavior-preserving steps, each keeping the pin green. For coordinated internal API reshapes, migrate every caller and delete the old API in the same wave ([principle-migrate-callers-then-delete-legacy-apis](../../principle-migrate-callers-then-delete-legacy-apis/SKILL.md)). For internal APIs with coordinated callers, avoid unnecessary compatibility paths. Preserve external consumers, serialized data and independently deployed versions; plan a staged migration when those contracts require it. Spot-check every rename against the actual files. Renames silently miss usages in strings, prose, and back-references. Delegate independent mechanical edits when useful using your configured refactoring model (role resolved through forge-setup; inherit when unconfigured) with a specific scope (file paths, the names being moved, the behavior to hold). Use the configured model role and supported host options, following Forge’s Delegation and models section.
6. Prove behavior is unchanged on the real artifact, not "it compiles" ([principle-prove-it-works](../../principle-prove-it-works/SKILL.md)). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface via the relevant available surface driver.
7. Confirm the change is worth keeping. The success measure is reduced reader load ([principle-minimize-reader-load](../../principle-minimize-reader-load/SKILL.md)). If the diff does not lower reader load somewhere, revert it.
8. Use local checkpoints for subtraction, reshaping and cleanup as needed. Consolidate one coherent commit per intended PR layer before first publication; do not publish a development transcript. Verify each behavior-preserving slice before the next. Apply **Publication and PR updates** (`opening-a-pr.md`).

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.
