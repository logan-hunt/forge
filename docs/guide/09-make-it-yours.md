# Make it yours

Keep adopter-specific rules in project or user instructions. Set model-role overrides and the default mode through [Forge setup](../../skills/forge-setup/SKILL.md). These settings live outside the installed package and survive replacement of its files.

Use the shared [Forge policy](../policy.md) for workflow boundaries, skills for task methods and host adapters for tool mechanics. Avoid overlapping overrides or copying repository-specific conventions into public Forge.

To change Forge itself, edit an owned source checkout and validate it before distributing an update. Do not patch an installed plugin cache. Review package updates against your intended behavior, and check existing discovery links and optional hook commands after moving or updating the package.

Reflect can propose durable improvements from scoped evidence. Human-origin records may establish preferences; unknown-origin patterns remain tentative and agent-origin content does not establish intent. Apply instruction changes only when authorized. Do not create unrelated backlog work or contact team chat automatically.
