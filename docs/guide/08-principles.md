# Principles

The Forge router keeps a principle index and links to leaf skills. Read the relevant leaf when using it; do not load every principle for every task or recite principle names in each reply.

Useful combinations include domain modeling plus boundary validation, idempotency plus ownership for retries, premise-testing after repeated failed fixes, and behavior tests plus real-artifact verification. Deletion and reader load guide implementation without overriding correctness.

Levers are preferred where they improve repeatability or proof. Existing effective tools count. Internal API migration assumes coordinated consumers; external contracts require compatibility planning. Structural enforcement should prevent a demonstrated mistake without growing the current task beyond authorization.
