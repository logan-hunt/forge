# Forge in T3

T3's current tool contracts take precedence over examples in skills. Resolve the short tool names below to the callable names exposed by the host, such as `mcp__t3_code__delegate_task`. Read each current schema before supplying arguments. Resolve role settings through [forge-setup](../../skills/forge-setup/SKILL.md) and verify those choices against `orchestrator_capabilities` once before first delegation, then again only after an error or a user-named provider change.

Use native subagents only for same-provider, inherited-settings tasks that finish in the turn: Codex `spawn_agent`, or Claude `Agent` with `run_in_background: false` when exposed. Other providers, model/settings requests, isolated child worktrees and background work use `delegate_task`. Put provider/model in `target`, reasoning settings in `target.options`, and use `isolation: worktree` for an isolated child checkout. Do not create a child's checkout in shell or request checkout setup in its prompt. A local delegate belongs to the current project; do not try to redirect it to a different local project. Report an unavailable model or incompatible project rather than silently substituting another execution route.

Checkout authorization follows [Forge policy](../policy.md#task-isolation-and-planning). Do not call `t3_worktree_handoff` as routine setup. Use it only for an explicitly requested move when the active host exposes and supports it. T3 owns isolated child checkouts through `delegate_task`.

Follow each task's returned `next`. Completion notifications replace polling. Cancel a replaced or no-longer-needed task with `task_cancel`. New review rounds are new tasks with consolidated briefs. Do not create top-level threads unless the user asks. Follow the host's rules for waiting, concurrency, child completion and thread links.

Read a named thread with `t3_thread_read` before answering about it; use its returned link verbatim. Request credentials with `request_secret`. Discover the host's environment tools before cross-machine work.

## PR lifecycle

After creating, taking over or pushing PRs, make `link_pull_request` or `link_pull_requests` the next call, using full URLs for every affected stack layer. Report a linking failure. Skip PRs only read or reviewed.

Follow the current host contract for `watch_pull_request`: register when asked to monitor or when the authorized task still waits on checks or reviews. Finish needed branch updates and pushes first, then follow the monitor's returned lifecycle and end the turn when required. Never run a parallel watcher, sleep loop, CLI watch or scheduled polling task. A watch persists across wakeups; do not register it again on each wake. Use `unwatch_pull_request` when the current host requires stopping it on handoff. One-shot status reads do not require a watch.

Children never watch PRs. Return each affected PR's full URL, actual head SHA, and checks and reviews state to the parent.

Monitoring does not authorize PR comments, initial publication, merging or deployment. Reading feedback to understand an authorized fix is allowed. Report feedback decisions in the conversation.

## Browser and visuals

When browser work is requested, call `preview_status` first, then `preview_open` if no tab can be automated. Prefer text `preview_snapshot` locators and `preview_evaluate` measurements; request an image only when someone needs to see it. Switch routes only when the tools are absent, `preview_open` reports unsupported, the user asks, or two preview calls fail on the same step. Quote the error before switching. Preserve tab/profile ownership and close task-created tabs unless the user needs them.

Do not use `preview_*` unasked to verify your own edits. For other permitted verification, use an available route under the shared [browser policy](../browser-work.md). A tool's presence does not expand authorization.

For inline visuals, pass the HTML to `html_preview`, inspect its screenshot and console output, then pass the same HTML to `html_render`. This is separate from browser automation; do not start a server merely to display a report. Follow the host's output contract for standalone images.
